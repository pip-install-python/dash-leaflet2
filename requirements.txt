# Documentation site requirements  (`python run.py`)
#
# The dash-leaflet2 PACKAGE itself needs only `dash>=4.1` — see pyproject.toml.
# A `pip install dash-leaflet2` user needs nothing on this list. Everything here
# exists to run the docs site and its live examples.
#
#     pip install -r requirements.txt
#
# Compatibility testing: scripts/compat_matrix.py installs this file with the
# pinned Dash line stripped, then installs one specific Dash version per venv.
# The pin therefore has to stay on a single line tagged `# COMPAT-MATRIX: dash`.
# ---------------------------------------------------------------------------

# --- Dash ------------------------------------------------------------------
# The [fastapi] extra pulls in FastAPI + Starlette + Uvicorn + WebSockets +
# Pydantic. DASH_BACKEND (read by lib/backend.py) flips between the bundled
# Flask backend and the FastAPI backend, which is what the sim pages exercise.
#
# Stable, deliberately. This pin is what the hosted documentation site actually
# runs, and 4.2.0rc3 — a release candidate — was serving production until the
# compatibility matrix confirmed 4.4.1 passes 70/70. The package itself is far
# looser (`dash>=4.1` in pyproject.toml); this pin binds only the docs site.
dash[fastapi]==4.4.1  # COMPAT-MATRIX: dash

# --- Docs shell ------------------------------------------------------------

# site needs Python >= 3.10. The dash_leaflet2 PACKAGE needs only >= 3.9.

dash-iconify==0.1.2
markdown2dash
python-frontmatter

./vendor/flexlayout_dash-1.1.0.tar.gz
# dash-clerk-auth: authentication for the HOSTED documentation site only.
# STAGED BUT NOT ENABLED — uncomment both lines to turn Clerk on.
#
# It is deliberately NOT a package dependency and never can be: pyproject.toml
# declares `dependencies = ["dash>=4.1"]` and ships `packages =
# ["dash_leaflet2"]`, so `pip install dash-leaflet2` never sees Clerk, never
# sees lib/auth.py, and never installs this. CI asserts that against the built
# wheel. Enabling it here changes the Render deployment only.
#
# Why it is commented out rather than simply added:
#
#   1. The package registers a `[dash_hooks]` entry point, which Dash
#      auto-imports during EVERY `Dash()` construction. Installing it therefore
#      puts it in the boot path of the whole site, configured or not — a broken
#      transitive dep takes down the documentation, not just sign-in.
#   2. Clerk satellite domains require a PRODUCTION Clerk instance. The 2plot.ai
#      primary is currently a dev instance (pk_test, *.accounts.dev frontend
#      API), and dev instances do not support multi-domain, so
#      CLERK_IS_SATELLITE=true against it cannot work yet.
#   3. Nothing depends on it today: /admin/control-board fails CLOSED without
#      Clerk (404 + the save callback refuses writes), and every docs page is
#      public by design.
#
# Turn it on once 2plot.ai is on a production Clerk instance AND
# https://leaflet.2plot.dev is in the primary's CLERK_ALLOWED_REDIRECT_ORIGINS.
# 0.9.0 carries the two satellite fixes lib/auth.py depends on; it is not on
# PyPI, and is vendored the same way across 2plotai, 2plotxyz and HoneyComb.
#   Used by: lib/auth.py, /admin/control-board
# ./vendor/dash_clerk_auth-0.9.0.tar.gz
# clerk-backend-api>=5.0.0,<6
