# ---------------------------------------------------------------------------
# Documentation site requirements  (`python run.py`)
#
# The dash-leaflet2 PACKAGE itself needs only `dash>=4.1` — see pyproject.toml.
# A `pip install dash-leaflet2` user needs nothing on this list. Everything here
# exists to run the docs site and its live examples.
#
#     pip install -r requirements.txt
#
# Compatibility testing: scripts/compat_matrix.py installs this file with the
# pinned Dash line stripped, then installs one specific Dash version per venv.
# The pin therefore has to stay on a single line tagged `# COMPAT-MATRIX: dash`.
# ---------------------------------------------------------------------------

# --- Dash ------------------------------------------------------------------
# The [fastapi] extra pulls in FastAPI + Starlette + Uvicorn + WebSockets +
# Pydantic. DASH_BACKEND (read by lib/backend.py) flips between the bundled
# Flask backend and the FastAPI backend, which is what the sim pages exercise.
#
# Stable, deliberately. This pin is what the hosted documentation site actually
# runs, and 4.2.0rc3 — a release candidate — was serving production until the
# compatibility matrix confirmed 4.4.1 passes 70/70. The package itself is far
# looser (`dash>=4.1` in pyproject.toml); this pin binds only the docs site.
dash[fastapi]==4.4.1  # COMPAT-MATRIX: dash

# --- Docs shell ------------------------------------------------------------
# NOTE: python-frontmatter 1.3+ imports typing.TypeGuard, so running the docs
# site needs Python >= 3.10. The dash_leaflet2 PACKAGE needs only >= 3.9.
dash_mantine_components==2.7.0
dash-iconify==0.1.2
# markdown2dash 0.1.2 declares `gunicorn>=21.2.0,<22.0.0` — a markdown parser
# pinning a WSGI server, and directly against the CVE-driven gunicorn>=23 floor
# below. pip cannot resolve both, so markdown2dash is NOT on this list and is
# installed on its own line WITHOUT its dependency graph:
#
#     pip install -r requirements.txt
#     pip install --no-deps markdown2dash==0.1.2
#
# The Dockerfile and CI both do exactly that pair. Its real runtime
# dependencies are listed here instead (dash, dash-iconify and
# dash-mantine-components are already pinned above), carrying markdown2dash's
# OWN declared ranges rather than bare names — with --no-deps there is no
# resolver left to catch an incompatible upgrade, so a future `mistune` 4.0
# would otherwise install silently and break the parser at import time.
docutils!=0.21
jsonpath>=0.82,<0.83
mistune>=3.0.1,<4.0.0
python-frontmatter
# 2.3.4 is the 2plot network standard floor, not a nice-to-have: it adds
# `resolve_site_title`, which is what stops a generic home-page name ("Home")
# or the Dash default becoming this site's published identity in the /llms.txt
# H1 and the llms viewer's brand chip. Below it, both fall back silently.
#
# Earlier steps on the same line: 2.2.0's merge semantics fixed the assign-vs-
# merge home-page stub, 2.3.3 stopped directive leakage into agent markdown and
# settled the OAI/Anthropic robots taxonomy. The [flask] extra is just
# flask>=2.0, already present via Dash.
dash-improve-my-llms[flask]>=2.3.4
python-dotenv>=1.0
pydantic>=2.0
requests>=2.31

dash-mui-charts>=1.2.3

./vendor/dash_emoji_mart-0.0.5.tar.gz

./vendor/flexlayout_dash-1.1.0.tar.gz
# dash-clerk-auth: authentication for the HOSTED documentation site only.
#
# It is deliberately NOT a package dependency and never can be: pyproject.toml
# declares `dependencies = ["dash>=4.1"]` and ships `packages =
# ["dash_leaflet2"]`, so `pip install dash-leaflet2` never sees Clerk, never
# sees lib/auth.py, and never installs this. CI asserts that against the built
# wheel. Enabling it here changes the Render deployment only.
#
# ONE OPERATIONAL RISK, worth knowing before you debug a dead site: the package
# registers a `[dash_hooks]` entry point that Dash auto-imports during EVERY
# `Dash()` construction. Installing it puts Clerk in the boot path of the whole
# documentation site, configured or not — so a broken transitive dependency
# takes down the docs, not just sign-in. Rollback is to comment these two lines
# and redeploy; /admin/control-board fails CLOSED without Clerk, so nothing is
# left exposed by doing so.
#
# 0.9.0 carries the two satellite fixes lib/auth.py depends on; it is not on
# PyPI, and is vendored the same way across 2plotai, 2plotxyz and HoneyComb.
#   Used by: lib/auth.py, /admin/control-board
./vendor/dash_clerk_auth-0.9.0.tar.gz
clerk-backend-api>=5.0.0,<6

# --- Deployment ------------------------------------------------------------
# gunicorn serves the Flask (WSGI) backend in the Dockerfile. The FastAPI
# backend is ASGI and needs uvicorn instead — already pulled in by dash[fastapi].
#
# gunicorn fronts every Flask deployment in this network, so the floor is the
# network's security baseline rather than a convenience: 21.x carried two HTTP
# request-smuggling CVEs (CVE-2024-6827, CVE-2024-1135), both fixed in 23.0.
# This is why markdown2dash is installed with --no-deps above — CI asserts the
# resolved version inside the built image, so a transitive pin can never drag
# the production server back under the floor without failing the build.
gunicorn>=26.0.0
